# Shared MCP, plugin and chat contract

`src/mvgrid/novi_sad/playground/agent_contract.py` is the authoritative project
workflow contract (1.0.0). The MCP server and in-app chat render its rules directly.
The plugin skill and contract asset are generated from the same source. The contract
standardizes terminology, evidence claims, causal algorithm requirements and focused
workflows; it does not select a model or promise model compliance.

## Algorithms and evidence

Use `ev_propose_strategy`, then `ev_specify_strategy` with the complete typed
definition. Explicit information, forecasts, action space, constraints, fallback,
test modules and limitations are required. Reproductions/adaptations require cited
mechanisms and differences; engineering baselines do not require invented papers.
Revision creates a new immutable record with the previous record as parent.

Implementation remains workspace work. A registered name is availability, not proof
that a saved specification was implemented. `ev_verify_strategy` runs only named
repository unittest modules through `scripts/run_strategy_checks.py`, captures actual
test counts, and binds its report to the specification, Python source, test helpers
and verification runner. Zero-test, skipped-only, failing and timed-out checks cannot
pass. The synchronous verification budget is 90 seconds, below the plugin's 120-second
tool timeout. Larger suites should run in the workspace. Source/test changes mark
previous reports stale. `checks_passed` proves those checks passed, not complete
specification conformance, causal correctness in all cases, or scientific superiority.

## Scenarios and execution

`ev_save_scenario` freezes labeled demand, fleet, timing, seeds, capacities and network
fingerprint. Parent revisions include field differences. `ev_prepare_experiment`
combines those conditions with algorithms, assertions and budgets; its typed choices
cannot override frozen seeds/capacities. A changed underlying network requires a new
scenario. Existing experiment IDs and direct experiment tools remain usable.

MCP outputs retain existing payload fields and add a typed `contract` envelope with
operation, execution, evidence and verdict. Domain output schemas describe key result
fields. Heterogeneous metrics and legacy specification payloads remain extensible.
Execution success is separate from scientific evidence. Incomplete prefixes cannot
produce a complete scientific verdict. Input/domain errors include actionable codes
and fields; the protocol also exposes schema validation failures before execution.

## Focused chat and compatibility

Chat selects explanation, algorithm, scenario, execution, comparison, diagnosis,
training or benchmark guidance. Users can override automatic focus. Explanation and
comparison intent takes priority over topic nouns; benchmark/training operations
retain their specialized guidance. Ordinary prose does not grant workspace edits.
The explicit Implement selector requires a saved modern specification and rejects
conflicting planning/negative instructions. Permission resets on the next turn.
The exact legacy `STRATEGY BUILD` command is retained for existing specifications;
modern specifications are revalidated even through that adapter.

Legacy tools/records remain readable. Legacy STRATEGY REVISE cannot update fields
introduced by the typed specification; use `ev_specify_strategy` for those changes.
Missing version pins are allowed for legacy callers. A provided version must share
the major version and must not be newer than the server. New plugin launches pin
`EV_AGENT_CONTRACT_VERSION`; incompatible installations fail before serving tools.
Chat fetches and sends the contract version with each new request.

## Synchronization and validation

After changing canonical rules, run `python scripts/sync_agent_contract.py`.
Use `--check` in validation and `--plugin <directory>` to check an installed copy.
Machine-specific launch paths are generated by `scripts/setup_playground_plugin.py`.
Install updated local plugin sources through the plugin-creator cachebuster/reinstall
workflow. New Codex tasks load the refreshed skill; the app chat uses current backend
instructions after restart.

Acceptance commands: `python -m unittest discover -s tests`,
`python scripts/verify_playground_mcp.py`, `npm --prefix web run build`, and
`node scripts/verify_chat_gui.cjs` (bundled Playwright on NODE_PATH).
The independent validator owns `tests/test_agent_contract_adversarial.py` and
`docs/agent-contract-validation.md`. Browser/chat lifecycle tests use an explicitly
fake CLI; real stdio tests exercise the actual MCP server and test subprocess.
These checks do not constitute an evaluation of live model instruction adherence.


## Cross-workflow validation boundary

The loss-accounting integration changed the default demand measurement to gross
supply including losses. The legacy scope/stress acceptance fixture explicitly pins
`measurement=load` because its exact linear baseline assertion is load-side; no
assertion or tolerance was weakened. Dedicated loss-accounting tests check gross/net
energy and incremental EV losses. The independent validator reproduced the prior
failure exactly. Spatial demand composition currently normalizes over the run horizon,
so equal gross input across different horizons need not mean equal spatial allocation
or net load. Treat this as a model limitation when interpreting such comparisons.


Final acceptance on 2026-09-10: the full repository suite passed 196 tests in
147.587 seconds, including all 21 independent adversarial tests. The 11 browser
checks, real 32-tool stdio MCP simulation lifecycle, benchmark discovery, production
build and live-app contract check passed. Evidence is recorded in
`artifacts/playground/evidence/agent-contract-validation.json` and the referenced logs.
The existing large JavaScript chunk warning and subprocess ResourceWarnings remain
non-fatal diagnostics; no test failure was suppressed.
